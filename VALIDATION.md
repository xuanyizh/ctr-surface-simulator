# Validation record

## Run-button feedback — 2026-10-07

The original browser run could queue all progress updates until the synchronous
calculation finished, making the Run button appear unresponsive. The solver
now yields between height-level Fourier transforms. The browser entry point
awaits the application, allowing the UI to display the current case, patch,
percentage and elapsed time during execution. A persistent completion message
points to the results below the button. Invalid settings show an explicit error.

All 29 physics tests passed after this change. The interface checks also passed,
including successful-run feedback, an oversized-FFT rejection, and preservation
of the previous result without displaying it as a newly completed run.
The numerical equations and default grid/padding are unchanged.

## Nonideal surface extension — 2026-10-07

Environment: Python 3.12.14, NumPy 2.3.5, Plotly 7.1.0, Streamlit 1.65.0.

`python -m unittest -v test_surface_model test_physics`: **29 tests passed**
(18 surface tests and the 11 existing geometry tests).

- Independent direct rectangular-tile summation agrees with FFT amplitudes
  at FFT nodes to absolute tolerance 1e-12, including variable qz.
- Off-grid complex interpolation converges when padding rises from 2 to 8;
  tested maximum amplitude error is below 0.003 for the seeded test points.
- The ideal-step limit recovers the signed rod positions/spacing and relative
  sinc-squared rod weights to absolute intensity tolerance 0.01.
- A flat Gaussian patch has the expected Fourier envelope. Integer-l height
  contrast vanishes in the normalized same-material model.
- Flat-base island coverage gives the expected anti-Bragg cancellation
  `(1-2*illuminated_coverage)^2`; a completed layer changes only phase.
- Height translation, ensemble intensity averaging, no-crossing enforcement,
  positive widths with fixed mean, shared-edge meandering, zero-disorder
  recovery and separate seeded feature streams are checked.
- Grid refinement samples the same stochastic realization at common coordinates.
- Unsupported Fourier coordinates are marked NaN; invalid reflection geometry
  is blank. Exported arrays load without pickle and reproduce the height map.

`python test_app.py`: existing interface checks plus the new five-case run,
data/settings export controls, stale-result warning and independent feature
switches passed. The default 512 × 256 surface / padding 4 / five-case run
also rendered through Streamlit AppTest without an exception. A local benchmark
took about 10 seconds for five maps; this is not a browser timing guarantee.

`surface_forward_preview.png` was generated by
`compare_surfaces.py` and visually inspected. It shows the actual
generated height maps and solver output on one shared scale. Matplotlib is
needed only for this optional preview script.

The extension was deployed to GitHub Pages on 2026-10-07 and checked in the
live Stlite / WebAssembly runtime at
https://xuanyizh.github.io/ctr-surface-simulator/ . The default 512 × 256 grid,

This browser has no WebGL, so the geometry used its 2D projection fallback.

These are mathematical and software checks, not agreement with experimental
data or a full reproduction of the paper's statistical model. See

## Limits of verification

The original local package was checked with AppTest and a scientific preview.
The GitHub Pages deployment was subsequently opened in a cloud browser and
ran the Python calculation with the default l=0.5 geometry. The test browser
has no WebGL support; a 2D projection mode was added and checked with AppTest.
The live 2D plots were visually inspected, and changing the selected detector
column updated its outgoing direction and hkl values. Export links generate
inline JSON/NPZ payloads, but download completion could not be confirmed in
the cloud browser (the download event timed out).
3D rotation has not been verified in a WebGL-capable browser. No Windows or
macOS machine was available to test the launch scripts.

This validates the implemented idealized geometry, not experimental calibration
or quantitative scattering intensities. The code has not been validated against
raw detector images, measured orientation matrices, structure factors or the
paper's complete roughness model. See README.md for all physics approximations.

## Default result for reproducibility

For the default oblique-step example, exact captured intersections are:

| Parent L | u (mm) | v (mm) |
|---:|---:|---:|
| -1 | 0.569 | -7.661 |
| 0 | 0.190 | -2.469 |
| 1 | -0.190 | 2.394 |
| 2 | -0.570 | 6.982 |

The detector spans ±9.6 mm in both axes. Even at symmetric centre l=0.5,
the spots are not exactly evenly spaced on the detector because the detector
samples the curved elastic shell. These are geometric centres; the teaching
brightness envelope can slightly shift an intensity maximum on a finite-width
rod. A captured geometric centre need not give an experimentally visible spot.
